# Risk report verification

The ten items do **not** all correspond to genuine bugs. Verified against current source:

1. **False positive.** `src/tools/DenyList.ts:78-90, 117-138`: `isDestructiveGitCheckout` matches `git checkout -- …` and is included in the built-in denylist. `test/unit/DenyListRecursiveDelete.test.ts` covers it.
2. **Real policy gap, approval mitigates exposure.** `src/tools/execHelpers.ts:138-176`: only `-Command`, `-EncodedCommand`, `-enc` are banned; `pwsh -File` runs model-selected script code (documented as allowed by `test/unit/BackgroundExitNotify.test.ts:120`). But `src/sidebar/ToolDispatch.ts:172-205` gates `exec_command`'s `headless` permission with confirmation. Thus the report's “no approval dialog” claim is false; approved script execution still has Forge's privileges.
3. **Conditional design risk, no bypass.** `src/tools/fileEditTools.ts:123-184`: `delete_file` is `delete` permission, resolves through workspace/extra-root containment, and defaults to trash. `src/sidebar/ToolDispatch.ts:172-200` confirms writes/deletes and marks recursive delete dangerous. A broad `extra_file_roots` entry plus approval can expose/delete user data; scope is explicitly configured.
4. **False positive.** `src/tools/execHelpers.ts:110-133`: embedded operators are argv data; exec is spawned with `shell:false` (`src/tools/BackgroundExecutionManager.ts:143-153`; foreground spawn likewise). Bare operator tokens are rejected. They cannot form a shell pipeline through this route.
5. **Real residual resource risk, bounded.** `src/tools/BackgroundExecutionManager.ts:132-139, 257-280`: no default timeout, so up to 32 jobs can run indefinitely until stopped, exit, timeout configured by caller, or extension disposal. Disposal kills them; accumulation is capped, not unlimited.
6. **False positive as stated.** `src/tools/execHelpers.ts:279-319`: truncated streams carry `*_truncated` and `*_note`; JSON retains `exitCode` and `kind` separately. A model could overlook a note, but truncation does not silently hide exit status.
7. **Conditional access risk; “unrestricted” is false.** `src/config/schema.ts:342` accepts user-listed absolute roots; `src/util/WorkspacePaths.ts:28-58` enforces containment to workspace or those roots. `read_file` uses roots (`src/tools/builtinTools.ts:44-105`); write/delete tools require permission confirmation. Sensitive data under an intentionally broad root can be read under normal read permission, so root selection matters.
8. **Partly real compatibility risk; report misstates `device`.** `src/backend/LlamaServerArgs.ts:22-43` sends configured `n_gpu_layers` (default 999) without VRAM preflight, so a load can OOM. `src/config/schema.ts:158-176` defines `embeddings.device`; it is not used by chat-server args. `src/backend/serverDiagnostics.ts:40-51` surfaces OOM and remediation. Installer smoke-test/update does not validate model-specific VRAM fit.
9. **False positive.** `src/extension.ts:430-440` wires `watchForgeConfig`; reload callback replaces runtime config and applies it to sidebar/pool. `SidebarProvider.ts:126-128` updates in-memory `active_model`, which manual config reload refreshes.
10. **False positive.** `src/sidebar/compactionLedger.ts:432-448` derives a ledger from transcript messages; no ledger file writes occur. `src/sidebar/compactionRecordedState.ts:115-142` is a synchronous pure merge; `CompactionService.ts:247-252, 423` builds then assigns the candidate after compaction checks. No append/delete interleaving exists.
