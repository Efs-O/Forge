Clanker · a mode wearing a button's clothes

Clanker isn't an action, it's a standing condition — ToolApprovalService:84 reads it on every approval and returns true without asking. Sitting it beside Stop puts persistent state in the row the eye scans for “what happens now”, one pointer-width from the button you hit under pressure. Claude Code's answer to the same problem is worth copying: permission mode is never a control in the action row. It lives as a dim status line directly under the input, cycles on Shift+Tab, colours itself when it's the dangerous one, and costs a one-time acceptance before it can ever be armed. The mode is a property of the box you type into.

↺

It survives reloads — quietly

high

Correction to the first pass: it does not reset. sidebarWiring.ts:118 restores it from workspaceState['forge.clankerMode'] at startup, and rememberClankerMode writes it on every toggle. It is workspace-scoped and durable — which makes the display more important, not less: the mode can be on from three days ago, and one amber pill in a button column is what's telling you.

ChangeOption A carries that weight properly — the field you type into is the thing that's armed, so the signal is where the risk is. What is genuinely missing is narrower: the flag is global to the workspace while the notice lands only in the tab where you typed /clanker.

⎘

Within an armed stretch, every call looks approved

high

The flip itself is already logged — SlashCommandHandler.ts:172 posts a notice both ways. What isn't: a write you confirmed and a write Clanker waved through at ToolApprovalService.ts:84 render identically, so within an armed stretch there's no per-call record.

ChangeTag auto-approved tool rows auto, as in specimen A. Deferred out of the layout pass — it means threading a flag from the approval service through ToolDispatch and the toolResult bridge message, four files for a signal the ON/OFF notice already gives at turn granularity.

⚠

Nothing gates the first arming

med

/clanker is availableWhileStreaming — correct, since mid-turn is when you want it — but that also means one slash command mid-stream removes every confirmation with no acknowledgement step.

ChangeOne-time modal on first use per install, the way bypass permissions is gated: state what stops being asked, note that recursive deletes still confirm, and that the per-turn checkpoint is the rollback. Never ask again.

Ten changes, keyed to the mock

1

The budget bar reads as empty

med

A full-width track sitting at 0 / 58k looks like a stalled progress bar, and it's the widest element on screen for a number nobody watches until it matters.

ChangeCollapse it to a 46 px chip beside the header icons. Let it grow a colour only past 70% and 90% — until then, it is a number, not a warning.

2

The session flyout pushes instead of floating

high

Opening it costs ~200 px of transcript permanently, and the current session appears three times: in the tab strip, again under OPEN, again as the header title. Four rows of history scroll inside a 160 px box while 400 px of empty transcript sits below it.

ChangeMake it an overlay anchored to the ◷ button — position:absolute over the transcript, dismiss on Escape or outside click. Drop the tab strip; the header line already names the current session and carries the 3 open ▾ switcher.

3

Session titles are the first line of the prompt

med

“44672” and “ping me 3 times at 15 second intervals.”” are not names anyone can navigate by, and conversationTitle.ts already exists to do better.

ChangeTitle from the first assistant turn rather than the user's opening keystrokes, and show 12 msg · 2h · qwen38 as the sub-line — model matters when you're picking a session to resume.

4

Both speakers get a box and a shouty label

med

YOU and FORGE in caps above bordered cards means the reading surface — assistant prose, the thing you actually read — is boxed in like a form field, and the eye has to cross two borders per exchange.

ChangeUser turns keep a 2 px accent rail and no box. Assistant turns run as plain text on the panel ground. Speaker is legible from indentation alone, so both labels go.

5

“Thinking” never says how much

med

A bare disclosure triangle gives no reason to open it and no signal that reasoning was expensive — which, on a shared output budget where thinking and the answer compete for the same tokens, is exactly what a user needs to see.

Change▸ Thought for 4.2 s · 380 tok. Same row, same fold, now a measurement.

6

Status is stranded below the void

high

The transcript is top-aligned, so “Feeding the GPU…” floats hundreds of pixels away from the text being generated. Two backend notices stay as separate centred italic lines forever, and the streaming indicator carries no elapsed time and no way to stop from where you're looking.

ChangeBottom-anchor the transcript (justify-content:flex-end) and put the live line at its tail with elapsed seconds, tok/s and an inline Stop. Collapse the boot notices into one Backend ready · 2.1 s.

7

The model bar is a full-width row for a value that rarely changes

med

It sits between the status line and the composer, splitting the two things that belong together, and spends a full row on a name that only needs to be recognisable, not complete.

ChangeFold it into the composer action row as qwen38-27b · q3kxl ▾ with the residency dot. Full name and slot count go in the tooltip and the picker.

8

Three stacked buttons, two of them primary

high

The vertical stack takes ~150 px of width from a 382 px column, so the textarea is squeezed to roughly half the panel. Worse, Queue and Stop are both live and both loud — nothing says which one Enter does. And ☠ CLANKER MODE in amber caps is the highest-contrast element on the screen for a mode you set once.

ChangeOne horizontal row under a full-width textarea: attach, model, spacer, and a single primary that is Stop while streaming and Send otherwise — Clanker leaves the row entirely (see above). Enter queues this for the next turn in 10 px below — say what the key does instead of building a button for it.

9

The Queue button is already redundant

high

In InputRow.tsx:346 the streaming branch renders #btn-send with the label “Queue” beside #btn-stop — but it fires the same submit that Enter fires at line 231, and the result already announces itself: QueuedPromptRow drops a dashed Queued — waiting on qwen38-27b row into the transcript with Steer and Cancel on it. So the button duplicates a key that works, to produce feedback that appears somewhere else.

ChangeDelete the streaming branch's send button. While a turn runs, the action slot holds Stop alone, and the queue is confirmed where it lives — in the transcript, next to the turn it's waiting on. The one thing lost is discoverability for a mouse-only user, which the Enter queues this for the next turn hint under the composer covers for a fifth of the pixels.
